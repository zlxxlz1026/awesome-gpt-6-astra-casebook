## 从“好看”改写为可检查的要求

孔雀案例的可借鉴之处是把视觉与交互同时写入需求；亲子空间则把场景对象和动作拆开。我们的建议是先完成“对象—输入—反馈”三列表，再描述美术。例如“用户拖动时旋转模型；松手停止；重置按钮回到初始视角”，比单独要求“沉浸式体验”更容易验收。

V8 案例也提醒我们：可视化细节丰富，不等于机械关系已验证。若用于教学，应另列需要核对的知识点和参考材料，并把未验证的机制标为示意。不要从演示图反推工程准确度。

## 原创需求模板：交互展品网页

以下是供改写的项目模板，不是任何收录作者的原文。方括号内容需要自行填写。

```text
目标：创建展示 [原创展品/主题] 的交互网页，面向 [目标读者]。
交付：提供源码、启动说明、依赖清单和已知限制。
场景：先完成一个主要对象和简单背景；使用 [我提供的素材/程序化形状]。
交互：拖动旋转、滚轮缩放、按钮重置视角；为触屏提供对应操作。
反馈：选中部件后显示名称与简短解释，界面文字使用 [语言]。
布局：窄屏时说明面板移到画面下方，按钮不能遮住主要对象。
约束：外部依赖和素材来源必须列明；未经验证的知识标为示意。
验收：按启动说明运行；逐项检查旋转、缩放、选择和重置。
记录失败项和修复步骤，不要把未执行的检查写成通过。
```

## 第一轮检查顺序

1. 按说明从新目录启动，确认入口和依赖齐全。先解决打不开、资源缺失、运行报错。
2. 检查每项输入是否产生规定的反馈，尤其是重置后能否回到可用状态。
3. 缩窄窗口，再用实际触屏设备检查。没有测过触屏时记录“未测”。
4. 再调整配色、光照和细节；记录测试设备与实际观察，避免仅凭视频判断性能。

如果第一轮失败，可用具体反馈继续：`复现步骤是 […]，预期 […]，实际 […]，日志 […]。先修复这个问题，说明修改并重新执行该检查。` 分享日志前去除密钥和个人数据。
